## 2026-04-28: Brainstorm Session — Architecture, UI, Data, Quality

### Architecture & Refactoring (Ripley)

**Critical Debt:**
- `App.tsx` (627 lines) is a god component handling auth, migration, community stats, filters, state, CRUD, and layout. Extract into route-level components: `GamesView`, `PlayersView`, `CommunityView`, `AppLayout`, `useAuthState` hook.
- `PlaythroughForm.tsx` (~700 lines) is monolithic. Decompose into: `CampaignSelector`, `InvestigatorRow`, `SideStoriesSection`, `PlaythroughFormShell`.
- Community stats does **collectionGroup query across all users** on every local playthrough change. Move to Cloud Function trigger. Remove `getAllPlaythroughs()` from client.

**Performance Issues:**
- Legacy migration effect runs on every render cycle, may loop via `onSnapshot`. Run once per session or remove entirely.
- `PlaythroughCard` not memoized; with 100+ items causes re-render jank. Wrap in `React.memo`.
- Two separate `useMemo` hooks compute duplicate player names. Consolidate.
- PRD calls for virtualization/pagination at 100+ playthroughs. None implemented. Add `react-window` when count > 50.
- No code splitting. Lazy-load `PlaythroughForm`, `CommunityStats`, `PublicHomepage`, `AuthDialog`.

**Architectural Gaps:**
- Only root error boundary. Add boundaries around `CommunityStats`, `PlaythroughForm`, each `TabsContent`.
- No loading states for mutations. Add `isSaving`/`isDeleting` flags to prevent double-submit.
- No offline support/optimistic updates. Enable Firestore persistence, consider optimistic UI.
- Type safety undermined by `as Record<string, any>` casts. Use proper `UpdateData<T>` typing.

**Priority Ranking:** (1) Move community stats to Cloud Function [P0], (2) Fix auto-migration loop [P0], (3) Split App.tsx/PlaythroughForm [P1], (4) React.memo list items [P1], (5) Lazy load [P2], (6) Error boundaries [P2].

### Data Layer & Performance (Ash)

**State Management:**
- `AuthenticatedApp` holds 13 `useState` hooks (filters, modals, form state) with prop drilling 2 levels deep. Extract into `useFilters()` hook and lightweight context for `playthroughs` + `currentUser`.
- No shared state between tabs; `CommunityStats` re-fetches on mount.
- Duplicate player name extraction in two `useMemo` blocks.

**Data Model Issues:**
- Player names are denormalized strings inside playthroughs. No `players` collection → renaming requires updating every playthrough.
- `InvestigatorAssignment` has 11 optional fields mixing legacy (`archetype`) with current (`archetypes`).
- Campaign identity is string-based with no ID reference. Brittle.
- **CRITICAL: Community stats rebuilt client-side from ALL users via `getAllPlaythroughs()` on every change.** With 100 users × 20 playthroughs = 2000 reads per change.
- No `createdAt`/`updatedAt` timestamps. Only user-entered `date` field.

**Performance Audit (Critical):**
- Community stats rebuild on every snapshot fires `getAllPlaythroughs()` (entire collectionGroup). O(N) full-table scan on every mutation. Additionally called redundantly on auth change, save, delete.
- Legacy auto-fix runs on every render. No guard to prevent re-running after fix. Can trigger write loops.
- `setAll` in `usePlaythroughs` recreates callback on every data change, writes ALL playthroughs (not just changed).
- No virtualization; all `filteredPlaythroughs` render at once.
- `resolveInvestigator` called repeatedly per-investigator per-render without memoization.

**Bundle Concerns:**
- Firebase SDK ~100KB gzipped (dominant).
- Both `@phosphor-icons/react` AND `lucide-react` installed; Phosphor used everywhere, Lucide unused → dead weight.
- `date-fns` used only for `formatDate`. Replace with `Intl.DateTimeFormat`.

**Hook Quality:**
- `usePlaythroughs`: abstraction B+, loading B, error D, memoization C, offline F.
- Missing: `useDebounce`, `useCommunityStats`, `useAuth`.

**Recommendations (Priority 1):**
1. Move community stats rebuild to Cloud Function. Estimated savings: eliminates thousands of redundant reads.
2. Gate legacy migration with `migrationVersion` field. Skip already-migrated docs.
3. Remove duplicate `rebuildCommunityStats` calls.

**Recommendations (Priority 2):**
4. Add `players` subcollection per user. Reference by ID in playthroughs.
5. Add `createdAt`/`updatedAt` timestamps.
6. Enable Firestore offline persistence.

**Recommendations (Priority 3):**
7. Data export format versioning: wrap in `{ version, exportedAt, data }`.
8. Search/filter by player name. (Exists on Players tab, not Games tab.)
9. Playthrough outcome tracking (win/loss/resign). No result field currently.
10. Virtualized list rendering when 30+.

**Scaling Projections:**
- 10-30: smooth.
- 50-100: noticeable jank.
- 200+: degraded; filter useMemo re-scans full array.
- 500+: broken; community stats rebuild untenable.

### Quality Gaps & Edge Cases (Lambert)

**Test Coverage: ZERO**
- No test framework. No vitest, jest, @testing-library/react, playwright, cypress.
- No test scripts. No `*.test.*` or `*.spec.*` files.

**P0 Tests (Risk):**

**P1 Tests:**

- Auth flows error mapping. Custom error messages for Firebase codes.

**P2 Tests:**

- `PlayerStats` computed statistics. Complex reduce/aggregation.

**Edge Cases — Unhandled (Data Layer):**
- **Firestore `onSnapshot` error**: No `onError` callback. Silent failure. User sees stale data indefinitely. **HIGH** — user thinks saving but isn't.
- **Concurrent edits** (2 tabs): `onSnapshot` syncs, but `setAll` races with listener. Auto-fix in both tabs = duplicate writes. **MEDIUM**.
- **`setAll` partial failure**: `Promise.all()` — if one fails, others succeed, inconsistent state. No retry/rollback. **MEDIUM**.
- **Offline writes**: Persistence not explicitly enabled. Writes may silently queue then fail. **MEDIUM**.
- **100+ playthroughs**: No virtualization/pagination. All rendered. **LOW** (perf, not data loss).

**Edge Cases — Form:**
- Empty investigator name with player name: auto-set to Unknown ✓.
- Date field cleared: no validation. Can submit empty string. Sort breaks. **HIGH**.
- Future dates: no max-date. Can log year 3000. **LOW**.
- Long custom campaign names: no `maxLength`. Inconsistent `max-w` on card. **LOW**.
- Rapid double-submit: no loading state on Save button. Create duplicates. **MEDIUM**.
- XSS via custom names: React escapes ✓.
- Investigator ID collision: duplicate check exists ✓.

**Edge Cases — Auth:**
- Token refresh failure: Firebase handles silently. Firestore call fails with permission error. Only caught by top-level ErrorBoundary. **MEDIUM**.
- Linking password to Google already having one: handled via `auth/provider-already-linked` ✓.
- Rapid sign-in: no rate limiting. Firebase may throttle. **LOW**.

**Edge Cases — Import/Export:**
- **Import with duplicate IDs**: No deduplication. Blind import overwrites or ID conflicts. **HIGH**.
- **Malformed archetypes**: Not validated against `Archetype` union. Displays with broken styling. **MEDIUM**.
- **Missing `campaignType`**: Only 4 fields validated. Missing field passes but crashes filter logic. **MEDIUM**.
- **1000+ entry import**: No chunking. `Promise.all` likely timeouts/quota. **MEDIUM**.
- **File size limit**: None. 100MB JSON freezes browser. **LOW**.

**Error Handling — Gaps:**

Works:
- ✅ Top-level `ErrorBoundary` + `ErrorFallback`.
- ✅ Toast notifications for CRUD success/failure.
- ✅ Auth error codes mapped to user-friendly messages.

Missing:
1. `subscribeToPlaythroughs` — no `onError` callback. Permission/network errors silent. Add callback.
2. Auto-migration — only `.catch(console.error)`. User never knows failure. Silent data corruption risk.

4. No retry logic. All Firestore operations fire-and-forget. Failed `addPlaythrough` loses form input.
5. `rebuildCommunityStats` called on every playthrough change. If Firestore rules change, throws repeatedly on every state update, flooding console.

## Decision: Community Stats Architecture

**Status:** CONSENSUS ACROSS ALL AGENTS  
**Finding:** `rebuildCommunityStats()` queries ALL users' playthroughs via `collectionGroup` on every client mutation. O(n) on platform data. Unsustainable at scale.
